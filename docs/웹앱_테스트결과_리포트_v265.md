## 분류와 안전 경계

- `photoSourceInfo()`는 기존 연결 필드만 읽는다. 서버 ID 또는 유효한 `relay:` 연결 문자열이 있으면 **연결 기록**으로 표시하며 파일 존재·접근 가능 여부·원본 동일성을 확인했다고 주장하지 않는다.
- 원격 파일은 기존 업로드 경로에서 압축된 사진일 수 있다. 미리보기와 빈 Blob을 원본 백업으로 간주하지 않는다.
- 현재 화면의 비어 있지 않은 File/Blob은 영구 보관이 아니다. 새로고침·앱 종료 전 원본 유지가 필요하다.
- PC 핸들은 기록만 확인하며 `getFile()`·권한 요청을 실행하지 않는다.
- 화면에 파일 URL/서버 ID/미리보기 이미지를 요청하지 않는다. 사진명·현장명·작업 내용은 텍스트로 이스케이프한다.
- 분류·정렬은 새 배열, 필터·페이지 수는 점검창 지역 변수다. 전역 검색·선택·dirty·원래 레코드·프로젝트를 수정하지 않는다.
- 사진 선택 확인/업로드/다른 잠긴 모달 중에는 진입을 막아 기존 작업을 보호한다.
- 점검창은 업로드·복원·자동 배정을 수행하지 않는다. 설정은 사용자가 `연결·대기열 확인`을 눌렀을 때만 연다.
- 저장 구조/직렬화 키/Apps Script/relay 큐/기존 업로드 함수는 변경하지 않는다. v201 사진 동기화 후보를 승격하지 않는다.
- 실제 휴대폰 권한·카메라·HEIC·운영 서버 파일의 실존·백업 결과는 이번 가상 자동 검사에서 확인한 범위가 아니다.

## 배포 후 대표 확인

1. 실제 사진 원본을 유지한 상태에서 앱 새 버전을 수동 적용한다.
2. 사진 도구 → 사진 보관 상태 확인으로 들어가 현장/작업명으로 검색한다.
3. 미리보기만 있는 사진과 현재 화면 파일이 서버 백업 완료로 표시되지 않는지 확인한다.
4. 전송 대기·오류가 있으면 연결 설정에서 확인한다. 이 점검 결과만으로 원본을 지우지 않는다.
