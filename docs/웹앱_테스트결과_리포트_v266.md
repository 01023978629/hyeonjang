# 아파트 프로젝트 동·호수 관리 — v266 로컬 후보

작성일: 2026-09-07

## 범위와 상태

- 사용자 요청: 프로젝트명을 아파트 이름으로 두고 그 안에서 동·호수를 관리.
- 기준선: v265 / main `08633ceda6090086c993873a463c1341b80b6494`.
- 후보: `hyeonjang-v266-aptunits`, `codex/apartment-unit-management-20260907`.
- **미배포**. 실제 프로젝트, PC 현장사진, Google Drive 자료는 수정하지 않았다.
- 현장 앱 스킬의 안전수칙과 읽기 전용 선행 검토에 따라 추정 배정·자동 병합을 제외했다.
- 서버, 유상 작업 승인, 접수함 발송, Apps Script, 비용·정산 계약은 변경하지 않는다.

## 사용하는 방법

1. 프로젝트에 `00아파트`처럼 아파트 이름을 등록하거나 기존 프로젝트를 선택한다.
2. 프로젝트 화면 → **동·호수 관리** → **동·호수 / 공용부 등록**.
3. 예: `101동 501호`, `102동 702호`, 공용부 `지하주차장`을 등록하고 작업 메모를 적는다.
4. 미지정 사진에서 사진과 배정할 위치를 선택한 뒤 **선택 사진 배정 저장**.
5. 각 세대의 **이 위치에 사진 추가**는 갤러리 선택 뒤 현장·동호수·작업 내용을 다시 확인한다.
6. 프로젝트를 바꾸면 동·호수 선택은 초기화된다. 기존 파일·프로젝트·작업명은 자동 변경하지 않는다.

## 데이터 및 안전 계약

- 프로젝트의 선택적 `aptUnits`: `{id,type,dong,ho,name,note}` 목록. 최대 500곳, 세대/공용부 지원.
- 사진의 `_aptUnit`은 `{project,unitId}`이며 백업에서는 선택적 `aptUnit`으로 보존한다.
- 기존 41개 직렬화 최상위 키는 유지한다. 새 필드가 없는 이전 자료에는 임의의 null 키를 추가하지 않는다.
- 정확한 프로젝트명 + 유효한 고유 세대 ID만 사진 연결 근거다. 표시명 변경은 같은 ID를 유지한다.
- 정규화 후 같은 동·호수/공용부는 중복 등록을 막는다. 잘못된 관리 목록과 모호한 연결은 추정 복구하지 않는다.
- 등록·메모 수정·사진 배정은 강제 안전 스냅샷 뒤 기존 원자 저장 경로를 사용한다. 실패 시 데이터 변경을 확정하지 않는다.
- 기존 사진은 미지정으로 유지한다. 세대 관리 시작 후 미배정 사진은 해당 세대의 완료보고 후보에 포함하지 않는다.
- 세대 이름 변경으로 기존 오더의 동·호수 표기와 달라지면 사진 조회를 다시 확인해야 한다. 오더를 자동 수정하거나 0원 오더를 생성하지 않는다.
- 관리 세대 사진은 레거시 동·호수 전역 검색에 섞이지 않는다. 접수 오더의 프로젝트 신원 확인 실패 시 전역 검색으로 돌아가지 않는다.
- 동일 Drive ID의 재다운로드에서는 연결을 보존한다. 이름만 같은 미확인 서버 사진으로 세대 기록을 대체하지 않는다.
- 로컬 재스캔에서는 정확한 경로의 모호하지 않은 연결만 승계한다. 파일명만 일치하거나 동일 경로의 세대 연결이 충돌하면 자동 승계하지 않는다.
- 복원 과정의 정리본 중복 병합에서도 서로 다른 세대 연결은 합치지 않는다.
- 사진 목록은 80장씩 더 보며 기존 선택과 배정 대상을 유지한다. 모바일 입력/버튼은 44px 이상이다.
