# 관리사무소 접수 따로 떼기 — 대표님 설치 순서 (2026-11-19)

## 무엇이 바뀌나요

지금은 관리사무소가 쓰는 접수 화면(만물웹 `office-request.html`)이 **현장웹 전체 자료를 맡은 중계 서버**를
그대로 부릅니다. 비밀번호(PIN) 로그인처럼 누구나 부를 수 있는 기능이 현장 자료 저장·불러오기와 한 서버
안에서 돌고 있어요.

이번에 관리사무소 접수만 받는 **새 Apps Script 프로젝트**를 따로 만들 수 있게 해 두었습니다.

- 관리사무소 화면은 새 주소만 부릅니다. 새 프로젝트에는 현장 자료를 읽거나 저장하는 코드가 없습니다.
- 현장웹 쪽 사용법은 그대로입니다. 관리사무소 접수함·접수·상태 바꾸기·단지 관리는 지금처럼 현장웹에서 합니다.
- 중계에 스위치를 켜기 전까지는 아무것도 바뀌지 않습니다. 코드만 먼저 넣어 두어도 안전합니다.
- 이 문서에는 실제 주소·ID·비밀값을 적지 않습니다. 값은 Apps Script 화면에서 복사해 붙여넣기만 하시고,
  채팅에는 **웹 앱 주소만** 보내 주세요(비밀값은 보내지 마세요).

## 준비 — 지금 쓰는 중계 프로젝트를 새 판으로 (값 안 바뀜)

1. script.google.com 에서 지금 현장웹이 쓰는 **중계 프로젝트**를 엽니다.
2. `OfficeIntake.gs` 내용을 저장소 `apps-script/OfficeIntake.gs` 새 판으로 통째로 바꿉니다. 다른 파일은 그대로 둡니다.
3. **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**. 주소는 그대로 유지됩니다.
   이 단계까지는 동작이 하나도 바뀌지 않습니다(스위치 속성이 아직 없으므로).

## 1. 새 프로젝트 만들기

1. script.google.com → **새 프로젝트**.
2. 이름을 `만물 관리사무소 접수` 처럼 알아보기 쉽게 바꿉니다.

## 2. 파일 붙여넣기

저장소 `apps-script-office-intake/` 폴더의 파일 네 개를 그대로 넣습니다.

1. 기본으로 있는 `Code.gs` 를 지우고, 파일 추가(＋ → 스크립트)로 세 개를 만들어 각각 붙여넣습니다:
   `IntakeMain.gs` · `OfficeIntake.gs` · `OfficeIntakePure.gs`
2. 톱니바퀴(프로젝트 설정) → **"appsscript.json" 매니페스트 파일을 편집기에 표시** 를 켜고,
   편집기에 나온 `appsscript.json` 을 폴더의 같은 파일 내용으로 바꿉니다.
3. 저장(디스크 모양).

> 중계 프로젝트의 `Code.gs` 를 새 프로젝트에 같이 넣지 마세요. 섞이면 새 프로젝트가 스스로 멈춥니다.

## 3. 속성 넣기 (이름만 적습니다 — 값은 복사해서)

새 프로젝트의 톱니바퀴 → **스크립트 속성** → 속성 추가:

| 이름 | 넣는 값 |
|---|---|
| `OFFICE_INTAKE_ENABLED` | `1` |
| `OFFICE_SESSION_SECRET` | 중계 프로젝트 스크립트 속성의 **같은 이름 값을 그대로 복사**. 중계에 없으면 새로 만든 긴 무작위 값(32자 이상)을 두 프로젝트에 똑같이 |
| `DRIVE_FOLDER_ID` | 중계 프로젝트의 **같은 이름 값을 그대로 복사**('만물인테리어' 폴더) |

`OFFICE_SESSION_SECRET` 이 두 프로젝트에서 다르면 관리사무소 로그인이 되지 않습니다.

## 4. setupOfficeIntake 한 번 실행

1. 편집기 위쪽 함수 고르는 칸에서 `setupOfficeIntake` 를 고르고 **실행**.
2. 처음이면 구글이 권한을 묻습니다(Drive·캘린더). 대표님 계정으로 직접 승인합니다.
3. 아래 실행 기록에 `준비됐어요. 접수 저장 파일 ID … ` 줄이 나옵니다. 이 **ID 를 복사해 두세요**(7단계에서 씁니다).
   'OFFICE_SESSION_SECRET: 있음' · 'OFFICE_INTAKE_ENABLED: 켜짐(1)' 도 같이 확인합니다.
4. 구글 드라이브 '만물인테리어' 안에 `관리사무소접수_분리` 폴더가 생깁니다. 지우거나 옮기지 마세요.

## 5. 웹 앱 배포

1. **배포 → 새 배포** → 톱니 → 유형 **웹 앱**.
2. 다음 사용자 인증 정보로 실행: **나**.
3. 액세스 권한이 있는 사용자: **모든 사용자**.
4. **배포** → 나온 웹 앱 주소(…/exec)를 복사합니다.
5. 그 주소를 브라우저에 붙여넣어 열면 `"service":"office-intake"` 와 `"ready":true` 가 보이면 정상입니다.

## 6. 주소를 Claude 에게

1. 5단계의 **웹 앱 주소만** Claude 에게 보내 주세요.
2. Claude 가 만물웹 `office-api.json` 의 접수 주소를 새 주소로 바꾸는 PR 을 만듭니다.
3. 대표님이 승인해 병합되면 몇 분 안에 만물웹 관리사무소 화면이 새 주소를 씁니다.

## 7. 중계 속성 스위치 켜기

만물웹 주소가 바뀐 것을 확인한 **바로 뒤에** 합니다.

1. **중계 프로젝트**(새 프로젝트가 아님) → 톱니바퀴 → 스크립트 속성 → 속성 추가:

| 이름 | 넣는 값 |
|---|---|
| `OFFICE_INTAKE_MODE` | `external` (소문자, 앞뒤 빈칸 없이) |
| `OFFICE_INTAKE_STORE_ID` | 4단계에서 복사한 접수 저장 파일 ID |

2. 저장하면 바로 적용됩니다(새 배포 필요 없음).
3. **현장웹을 한 번 엽니다.** 관리사무소 접수함이 동기화되면서 등록된 단지 목록이 새 프로젝트로 넘어갑니다.
4. 1분쯤 뒤 관리사무소 화면에서 시험 단지로 로그인해 봅니다.

이제 옛 중계 주소로 관리사무소 기능을 부르면 '관리사무소 접수 주소가 옮겨졌어요' 오류가 납니다(정상).
현장웹에서 단지를 중지하거나 PIN 을 바꾸면 새 프로젝트에는 30초 안에 반영됩니다.

## 되돌리기

문제가 생기면 이 순서로 되돌립니다. 지우는 것은 없습니다.

1. 중계 프로젝트 스크립트 속성에서 `OFFICE_INTAKE_MODE` 를 **삭제**합니다. 바로 예전처럼 중계가 관리사무소
   접수를 받고 예전 접수 파일을 씁니다.
2. Claude 에게 '관리사무소 접수 되돌려 줘' 라고 하면 만물웹 `office-api.json` 주소를 중계 주소로 돌리는 PR 을 만듭니다.
3. 새 프로젝트에서 `OFFICE_INTAKE_ENABLED` 를 `0` 으로 바꿉니다.
4. 켜져 있던 동안 새 프로젝트로 들어온 접수는 `관리사무소접수_분리` 폴더에 그대로 남아 있습니다.
   되돌린 뒤에는 현장웹 접수함에 보이지 않으니, 남은 접수가 있으면 Claude 에게 옮겨 달라고 해 주세요.

## 알아 두실 것

- 지금(11/19) 현장웹 자료 기준으로 관리사무소 접수는 0건이고 등록된 단지도 없어서, 옮길 접수는 없습니다.
- 켜져 있던 동안에도 예전 접수 파일(`관리사무소접수.json`)은 건드리지 않습니다.
- 새 프로젝트는 같은 구글 계정으로 돌기 때문에 구글 드라이브 권한 자체는 같습니다. 달라지는 것은 공개 주소에서
  돌아가는 코드(현장 자료 코드 없음)와 서버 잠금·실행 시간이 따로라는 점입니다.
