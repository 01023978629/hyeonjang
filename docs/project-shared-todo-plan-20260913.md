# 현장별 공유 할일 v296 — 승인 후 구현·검증 기록

## 요청과 확인

사용자는 오늘 할일에서 현장을 선택해 작업을 입력하고 다른 사용자도 변경 내용을 확인하기를 요청했다. 직원들은 같은 서버·드라이브 자료를 사용한다고 확인했다.

구현 기준: main 9460da4, hyeonjang-v295-todonav. 후보: hyeonjang-v296-sharedtodo.
사용자가 전용 서버 API·웹 구현 및 검사 후 배포 계획에 “배포 진행”으로 승인했다.
구현은 완료했으며 실제 배포·검사 완료 여부는 아래 증거를 기준으로 판단한다.

## 현재 코드에서 확인한 제한

- todoView는 입력할 현장은 고를 수 있으나 목록은 모든 현장이 함께 표시된다.
- 할일과 팀 업무는 state.notes에 저장된다. relay 저장은 사진·장부 등을 포함한 전체 JSON과 파일 단위 revision을 사용한다.
- relayBoot는 다른 기기 변경을 자동 적용하지 않고 불러오기 안내만 한다.
- 직접 Drive 저장 gdSave는 revision 조건 없이 전체 파일을 갱신한다. 구버전의 전체 덮어쓰기와 혼용하면 할일만 안전하게 병합할 수 없다.
- 서버 할일만 읽은 뒤 전체 자료 기준 __relay.rev를 올리면 나머지 낡은 자료를 덮을 수 있으므로 하지 않는다.
- 기존 직원 포털의 관리사무소 작업지시는 단지별 권한·상태 모델이 달라 일반 현장 할일로 대신 사용하지 않는다.

## 제안 범위

1. 오늘 할일 상단에 현장 선택, 전체/선택 현장 보기, 할일 입력과 수정·완료 기능을 둔다.
2. 현재 중계 서버의 인증 연결은 재사용하되 할일 전용 API와 독립 저장 파일을 추가한다. 사진/장부 원본 JSON과 기존 relay 동작은 보존한다.
3. 각 작업의 revision과 요청 식별자로 동시 수정·중복 전송을 감지한다. 변경 충돌은 입력을 남겨 두고 최신 내용을 확인하게 하며 자동 덮어쓰지 않는다.
4. 다른 직원은 오늘 할일 화면을 보고 있는 동안 주기적으로 최신 목록을 확인한다. 수동 새로고침, 마지막 성공 시각, 저장 중/공유 완료/실패·미전송 상태를 구분한다. 수신을 확인하지 않고 동료가 읽었다고 표시하지 않는다.
5. 기존 개인 할일은 보존한다. 기존 기록을 자동으로 전부 공유하거나 삭제하지 않고 사용자가 선택해 공유하는 경로를 둔다.
6. 저장 경로를 공유하는 사람들의 회사 내부 할일이며, 입력한 담당자 이름은 로그인이나 접근권한이 아니다. 새로운 직원별 열람 제한·계정 생성은 별도 범위다.

## 승인 범위와 운영 안전

AGENTS.md의 기존 apps-script relay 서버 변경 제한에 대해 이번에 승인된 범위는 `SharedTodo.gs` 추가와 인증 성공 뒤 조건부 dispatch 한 줄이다. 원래 사진 relay action의 동작은 변경하지 않는다. 실제 회사 자료·계정·토큰·권한·Script Properties는 변경하지 않는다. OAuth 재승인이 필요하면 사용자에게 안내한다.

운영 중계 프로젝트와 직원 포털 프로젝트는 서로 다르다. 기존 exec 배포와 일치하는 중계 프로젝트를 API로 확인했다. 운영 HEAD=배포 version 6이며 소스 5파일을 저장소 밖에 백업했다. 운영 `Watchdog`는 로컬과 다르므로 운영본을 보존하며 폴더 전체 push를 하지 않는다. Apps Script와 Pages 배포는 별도로 확인한다.

## 구현 내용

- 하단 오늘 할일: 서버 연결이 있으면 회사 공유 목록. 현장 선택·필터·입력·수정·완료·목록 제외.
- 보이는 동안 30초 간격 최신 조회, 수동 조회, 저장 상태와 마지막 확인 시간 표시. 푸시/읽음 확인은 아니다.
- `_현장_공유할일/현장_공유할일_v1.json` 별도 저장. 기존 사진·장부 JSON 및 `__relay.rev`는 수정하지 않는다.
- 작업 revision과 성공 요청 영수증을 동일 잠금·동일 파일 쓰기로 저장. 같은 작업 충돌 시 자동 덮어쓰지 않는다.
- 응답 불명 요청은 정확한 서버·토큰·기기 조합의 해시 키에 IDB 보관. 동일 요청 ID로 재확인하며 인증 오류로 임의 폐기하지 않는다.
- 같은 브라우저 여러 탭의 대기 요청 예약·정리는 IDB 단일 readwrite 트랜잭션으로 비교 후 처리한다. 이전 ACK가 새 요청을 지우지 않는다.
- 기존 개인 할일은 별도로 보존. 선택한 한 건을 공유 초안으로 복사한 후 사용자가 공유해야 한다. 대시보드 집계도 기존/공유를 구분한다.
- 오프라인 신규 입력은 화면에 유지되지만 서버 공유 완료가 아니며 자동 전송하지 않는다. 화면을 닫기 전 사용자가 입력을 보관해야 한다.
- 같은 회사 연결을 가진 사용자 모두 읽기/수정 가능. 직원별 권한·담당자 로그인·읽음 확인은 이번 범위가 아니다.

## 검증 기준

- 가상 사용자 A/B의 별도 브라우저: A 현장별 추가 → B 최신 조회 → 완료/수정 반영.
- 같은 작업 동시 수정 충돌, 다른 작업 동시 변경 보존, 응답 유실 후 동일 요청 재시도 중복 방지.
- 미인증·권한 오류·오프라인·서버 실패 시 공유 완료로 표시하지 않기.
- 닫힌 화면/이전 연결의 늦은 응답 무시, 목록 갱신 중 입력 및 선택 유지.
- 실제 사진·장부·개인 할일·계정 변경 없음, 구버전 전체 데이터 저장으로 공유 할일이 지워지지 않기.
- 신규 회귀와 보호 변이, 최종 전체 회귀, 공개 버전·모바일 확인, 두 실제 사용자 확인을 각각 구분해 보고.
