# 현장 웹 레벨 3 준비도와 개발 순서

확인일: 2026-09-09. 운영 기준선: main `7971987`, 공개 화면 `hyeonjang-v273-officeconnect`.
후보: `hyeonjang-v274-recoveryguard`. **현재 운영 레벨 3 달성을 선언하지 않는다.**

## 목표의 의미

대표는 개발 가능 항목을 확인하고 레벨 3에 도달하도록 요청했다.
기존 문서에 숫자형 레벨 3의 공식 정의는 없으며 의미를 확인 중이다.
이 문서의 제안 기준은 외부 인증이 아닌 내부 운영 기준이다.

1. 기록: 사진·견적·현장별 자료를 저장하고 찾는다.
2. 연결: 현장·동호수·작업일지·견적·관리사무소 접수가 이어진다.
3. 검증된 운영: 누락을 알려 주고, 승인된 처리의 실제 결과와 실패를 확인하며,
   휴대폰 재시작·통신 실패 후에도 자료를 복구할 수 있다.

기존 `aiOpsSelfCheck` 점수는 활동 로그와 큐 상태의 참고값이다.
화면을 열었다는 실행 기록이나 빈 대기열만으로 실제 업무 완료·원본 보관·권한 검증을
입증할 수 없다. 점수를 높이거나 자동 실행 권한을 넓혀 레벨 3를 달성한 것으로 처리하지 않는다.

## 확인한 현재 기능

- 사진 추가 시 현장/작업명 확인, 읽기 전용 보관 상태, 사진 작업일지·동호수 필터.
- 아파트 프로젝트 내 세대/공용부 관리와 견적 날짜·프로젝트 지정.
- 모바일 더보기 검색·즐겨찾기, 관리사무소 최근 조회/전송 대기/차단 상태.
- 공개 사용 중 화면에서 v273 빌드를 확인했다. 실제 자료 수정·복원·전송은 하지 않았다.

## 이번에 보완하는 안전 문제

### 1. 복구 전 안전판 실패 시 중단

`backupHistory`의 기존 복구 버튼은 `hjSnapshot`이 false여도 `applyData`를 호출했다.
실제 함수를 합성 저장소에서 실행해 재현했다.

후보는 `hjRestoreSnapshot`에서 저장 성공(true) 이후에만 복구한다.
현재 데이터가 비어 있어도 명시적으로 안전판을 남긴다. 중복 실행을 차단하고,
복구 전 스냅샷 저장 단계의 실패·예외는 현재 자료를 적용 변경하지 않은 채 안내한다.
필수 files 배열이 없는 손상 기록은 적용 전에 차단한다. 정상적인 빈 files 배열은 허용한다.
applyData 자체의 중간 예외를 원자적으로 되돌린다는 보장은 이번 범위에 없으며,
해당 실패 시에는 이미 저장된 복구 직전 안전판을 확인하도록 안내한다.
이 안전판은 기기 내부 스냅샷이며 클라우드 저장 성공이나 원본 사진 복원을 의미하지 않는다.

### 2. 동기화 대기열 읽기 실패 시 기록 보존

기존 `relayQueueGet`은 IDB 읽기 실패를 빈 배열로 바꾸어, 새 항목을 저장할 때
기존 대기 항목을 덮어쓸 수 있었다. 합성 upload 기록으로 재현했다.

후보는 `relayQueueReadStrict`로 읽기 실패와 진짜 빈 큐를 구분한다.
추가·재전송 완료 처리·실패 항목 정리는 읽기와 저장 성공 확인을 거친다.
목록 조회 실패는 0건이 아닌 '확인 불가', 서버/큐 모두 실패하면 '보관됨' 대신 실패를 표시한다.
사진 추가나 실제 대기열 정리를 실행한 것이 아니라 앱 코드의 실패 처리를 보완한 것이다.

## 아직 통과했다고 말할 수 없는 항목

- `workLogSave`와 `reportPhotos`는 현장+날짜 중심이므로 동호수별 기록 분리 보완이 필요하다.
- `aiExecuteTask`의 화면 열기 성공과 `aiOpsOutcomeStats`의 실행 성공률은 업무 해결률과 다르다.
- 현재 사진 중계는 압축 파생본을 업로드하며, 서버 `uploadFile_`의 멱등성과 큐 재전송 후
  로컬 사진 ID 연결은 후속 검토 대상이다. 이번 대기열 보완만으로 중복 없는 전송을 보증하지 않는다.
- 서로 겹치는 대기열 변경의 원자성은 이번 IDB 실패 보완과 별개의 후속 검증이다.
- `apps-script-office-ops/conversion-promotion.json`의 비활성 상태를 변경하지 않는다.
- 실기기 카메라/갤러리, 운영 계정 권한, 서버 원본 복구는 모의 검사로 대체하지 않는다.

외부 업로드·PR·병합·배포·고객 발송·운영 자료 삭제는 수행하지 않는다.

## 레벨 3 운영 인수 검사안

아래는 앞으로 수행할 검사안이며 이번에 실행한 실제 업무가 아니다.

- 자료 안전: 저장 공간 오류·통신 끊김·손상 백업에서 기존 자료가 유지되고,
  성공과 실패가 다르게 표시되어야 한다. 현재 후보의 합성 검사 범위부터 확인한다.
- 완료 판정: 화면만 열고 취소한 작업은 미완료로 남아야 한다. 실제 저장 결과를
  확인한 작업만 해결로 집계한다. 발송 기능이 꺼져 있으면 발송 완료는 만들지 않는다.
- 세대 분리: 같은 날 같은 아파트의 두 세대에 서로 다른 사진·일지를 등록했을 때,
  각 세대 보고서에 상대 세대 자료가 섞이지 않아야 한다. 기존 위치 미지정 자료는 그대로 둔다.
- 휴대폰 복구: 대표가 승인한 시험 사진으로 촬영→대기→앱 종료→재실행→재접속을
  확인한다. 원본/미리보기·중복 수신·프로젝트 연결을 각각 검사하며 원본을 삭제하지 않는다.
- 권한: 별도 시험 단지 A/B와 시험 역할 계정을 사용해 같은 단지 내 허용 작업과
  다른 단지 접근 차단을 서버 응답까지 확인한다. 실제 고객 자료로 시험하지 않는다.
- 인수: 각 항목은 확인됨/미통과/미검증을 기록한다. 코드 검사 통과, 운영 배포,
  실기기·실계정 확인이 모두 끝나야 내부 기준의 운영 레벨 3 도달로 보고한다.
