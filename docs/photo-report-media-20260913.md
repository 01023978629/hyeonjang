## 사용자가 달라지는 점

1. 사진 작업일지에서 전체/사진/동영상으로 좁혀 본다. 조회 결과와 현장 전체 수량에 사진 장수와 영상 개수를 구분한다.
2. 동영상은 첫 장면 사진 대신 형식(MP4/MOV 등)과 재생 버튼으로 표시한다. 현재 조회된 현장의 영상만 차례로 재생한다.
3. 재생창을 닫거나 뒤로 가도 작업일지의 검색·필터·사진 선택이 유지된다. 원본이 없으면 재생이 된 것처럼 보이지 않고 연결 안내를 표시한다.
4. 작업일지 글·TXT·명시적으로 요청한 AI 초안에 실제 조회 종류와 수량이 반영된다. AI가 사진·영상을 직접 봤다고 표현하지 않는다.
5. 사진 이미지 합성에는 영상이 들어가지 않는다. 로딩 중 종류·현장·위치·조회 기록이 달라져도 오래된 결과를 저장하지 않는다.
6. 일일 작업보고서에서 빠지던 사진이 정상 표시되고 긴 본문·사진 4장도 하단이 잘리지 않도록 높이가 자동 조정된다. 불러오지 못한 사진 수는 명시한다. PDF도 글·사진 경계에서 페이지를 나누며 비율을 유지한다.

## 기술 변경과 안전 경계

- `photoReportData`의 정규화된 `mediaType`와 종류별 count, 미디어 판별을 포함하는 `recordKey`.
- 빈/중복 영상 ID는 재생하지 않으며 HTML 특수문자는 데이터로 이스케이프한다.
- 영상 재생은 기존 `openLightbox`를 현재 조회의 명시적 ID 목록으로 호출한다.
- 라이트박스가 모달 위에서 열릴 때만 nested history를 추가한다. 모달을 inert로 잠그고 재생창 내부 초점을 유지한 뒤 기존 버튼으로 복귀한다.
- 일일 보고서는 이미지 로더가 반환한 `img`를 그리며 `url`은 성공·실패 모두 finally에서 회수한다.
- 일일 보고서의 PDF만 선택적 `pageBreaks`를 사용하며 다른 문서는 기존 3인자 `__docExport` 경로를 유지한다.
- 영상 컨트롤 뒤에 명시적인 `닫고 돌아가기` 버튼을 두어 브라우저 기본 컨트롤 내부 Tab은 가로채지 않는다.
- APP_BUILD, service worker C, `version-sync.check.js`의 후보 버전을 함께 변경한다.
- `_현장.json`, 사진 원본, 실제 프로젝트·견적, Drive/Apps Script 설정·계정·접수 자료는 수정하지 않는다.
- 새 저장 키, 자동 업로드, 자동 공유·발송, 운영 레벨 상승 표시는 추가하지 않는다.
