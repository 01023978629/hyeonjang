# 사진 위치 혼합 방지

운영 main `ce3b80ee2770d1e79af4c2b5bada125245161f64` 기반의 `codex/photo-location-20261013` 수정 후보다. 현재 개발 브랜치의 다른 기능은 포함하지 않는다. 빌드 식별자는 `hyeonjang-v342-photolocation`이다.

2026-10-13 사용자가 검증 결과 안내 후 "반영해줘"로 브랜치 업로드·PR 검사·main 병합·GitHub Pages 배포를 승인했다. 아래 로컬 검증 기록은 배포 준비 시점의 결과이며 실제 PR/Pages 결과는 해당 실행 기록과 배포 영수증으로 확인한다.

## 문제와 변경

이전에는 같은 시간대라면 GPS 없는 사진도 GPS 사진과 같은 방문이 됐다. 주소 조회는 대표 좌표의 결과를 묶음 전체에 저장했고 일부만 현장에 배정된 경우 나머지 사진도 확실한 추천 대상으로 처리했다.

- 유효한 위도·경도가 있는 사진과 위치 미확인 사진을 분리한다. 알려진 서로 다른 현장 배정도 한 묶음에 넣지 않는다.
- GPS 없는 사진끼리의 시간 탐색 편의는 유지하되 `사진 묶음 / 위치 미확인 · 시간 기준 묶음`으로 표시한다. 같은 현장이라는 뜻이 아니며 나머지 사진의 배정은 참고 제안으로만 표시한다.
- 자동 주소 조회·전체 조회·다시 조회는 각각의 사진 GPS 및 거리 범위를 확인한다. 수동 건물명을 보존하고 조회 중 복원·삭제·좌표·배정·주소 변경이 발생한 대상에는 늦은 응답을 적용하지 않는다.
- 예전 저장 주소를 지우거나 교정하지 않는다. GPS 없는 주소는 상세 화면에서 `위치 미확인 · 저장 주소`로 표시하며 묶음 대표 위치로 사용하지 않는다.
- 원본 파일, ID, 현장 배정, 날짜, 공정, 작업명, Drive 식별자와 저장 스키마를 유지한다. 파일명으로 실제 현장이나 날짜를 추정하여 덮어쓰지 않는다.

## 검증

- 기존 운영 코드(`ce3b80e`)와 수정 코드에 동일한 합성 기록을 넣어 직접 비교했다. 기존은 25장이 하나의 GPS 대표 위치를 가진 한 묶음, 수정은 GPS 있는 4장과 GPS 없는 21장 두 묶음이었으며 양쪽 모두 입력 기록 자체는 보존됐다.
- 신규 단위 검사 19/19: GPS 4장과 위치 미확인 21장의 분리, 정상 위치 묶음, 현장 충돌, 배정 추천, 주소 3경로, 수동 주소, 지연 응답, 원본 필드 불변.
- 신규 화면 검사: 4/21 분리, 미지정 유지, 위치 미확인 표시, 사진 상세, 모바일 가로 넘침 없음, pageerror 0.
- 변이 검사 6/6: GPS 없는 사진 합치기, 현장 구분 제거, 시간 기준 확실 추천, 주소 제한 제거, 지연 응답 보호 제거, 확인 필요 표시 제거를 실제 실패로 검출했다. 변이는 별도 `node tests/photo-location.mutations.js`로 실행하며 전체 검사 러너에 자동 포함되지 않는다.
- 기존 사진 정렬·추천·위치 표시 검사 통과.
- 독립 읽기 전용 검토: 차단할 high/medium 문제 없음. 동일 주소를 새로 적용하지 않을 때의 안내 문구는 검토 의견에 따라 수정했다.
- 전체 회귀 `node tests/run-all.js`: **231개 중 230 통과, 1 실패**, 종료코드 1, 19.2분, 동시 3. `menu-schedule.e2e.js`의 40장 공정 버튼 검사가 실패했다. 서로 다른 현장을 분리하면서 묶음 수가 늘어 초기 12묶음만 표시된 것이 원인이다. 실제 더 보기 버튼으로 전체 사진을 펼친 뒤 기존 40장·공정표 호출 수 단언을 그대로 검사하도록 보완했다. 제품 코드는 이 전체 실행 이후 변경하지 않았다.
- 보완 후 최종 관련 검사 **8/8 통과**, 종료코드 0, 재시도 없음: syntax, version-sync, photo-location 단위/화면, menu-schedule, geocode-label, photo-order, photo-suggest. 전체 231개를 다시 실행한 결과라고 표현하지 않는다.
- `snapshot-restore-guard.e2e.js`는 전체 실행 중 첫 시도 실패, 러너의 단독 재시도에서 통과했다. 이 검사나 복원 제품 코드는 수정하지 않았으며 최초 실패 원인은 확정하지 않았다. 다른 실패는 없었다.
- 최종 코드의 변이 검사도 다시 실행하여 6/6 검출을 확인했다. `git diff --check` 통과.

초기 신규 화면 검사는 빈 외곽 요소 `#lightbox`의 가시성을 기다려 실패했다. 실제 닫기 버튼의 가시성을 기다리도록 수정했다. 다음 검사는 기존 렌더러의 임시 중복 표시 필드 `_dup`/`_dupOf`까지 원본 필드로 비교해 실패했다. 이 두 화면용 필드만 제외하고 다른 모든 필드가 유지되는지 검사하여 통과했다. 검사 실패를 제품 통과로 기록하지 않는다.

## 반영 범위와 한계

검증에는 합성 기록만 사용했다. 사용자의 실제 사진 기록이나 파일을 변경하지 않았고 현재 브라우저에 수정 코드를 주입하지 않았다. 4/21은 동일 조건을 만든 합성 검증 수량으로, 운영 자료를 수정한 결과가 아니다.

이미 저장된 잘못된 주소와 파일 수정일에서 온 날짜는 이번 수정에서 자동 교정하지 않는다. GPS 없는 사진 21장의 실제 현장 배정도 자동 실행하지 않는다. 위 로컬 검증을 마친 시점에는 main 병합, 원격 업로드 및 운영 배포를 수행하지 않았다.
