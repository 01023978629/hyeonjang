## 운영 기능 목록 및 이번 구현

| 운영할 때 필요한 일 | 이번 처리 |
| --- | --- |
| 앱을 켜고 남은 일 확인 | 첫 화면 `오늘 현장 업무`: 미완료/밀린 할 일 수와 기존 할 일 창 바로가기. 현장 0개일 때도 사용 가능 |
| 현장으로 출발하기 전 준비 | 오늘/다가오는 일정에서 현재 준비물 목록의 체크 진행률 확인, `출발 전 챙김` 바로가기 |
| 작업 후 기록 남기기 | 해당 일정 ID의 `작업일지`를 첫 화면에서 바로 열기. 자동 작성/발송은 없음 |
| 현장·자료 찾기 | 첫 화면 통합 검색 연결, 찾은 현장으로 정확히 이동. 남은 검색/공정 필터 해제, 보관 상태와 사진 선택은 보존 |
| 여러 현장 할 일 입력 | 30개 현장 제한 제거, 반복 추가 시 선택 현장 유지, 삭제·동명이인 현장은 저장 중단하고 초안 유지 |
| 동기화 도중 잘못된 체크 방지 | 준비물 창이 열린 뒤 일정 객체·내용·목록 변경/삭제/ID 중복 시 재확인 안내, 이전 객체에는 저장하지 않음 |
| 현장 사진·영상 보고 | 앞서 완성한 v289의 종류별 검색/집계/영상 재생 및 사진 보고서 PDF 페이지 분할을 함께 포함 |

미완료 집계는 기존 `notes[].todo`만 읽는다. '밀린'은 작성일이 어제 이전인 미완료 항목이며 납기 지연을 추정하지 않는다.
준비물은 기존 `hjPrepFor`의 참고 목록과 `schedule[].prep` 체크값의 교집합이다. 빈 목록을 '준비 완료'로 표시하지 않는다.
메인 버튼은 그대로 두고 텍스트만 갱신하여 닫기/Esc/뒤로가기 후 초점 복귀를 유지한다.
대화에서 할 일 담기 역시 `hjTodoAdd` 공통 경로를 통해 첫 화면 건수를 갱신한다.

## 다음 개발 우선순위 — 이번 배포에는 포함하지 않음

1. **실패 업로드만 재시도**: 현재 세션의 실패 파일과 기존 레코드를 재사용해야 한다. 새 레코드 생성, 성공/큐 대기분 재전송을 막고 삭제·중복 ID를 검증한 뒤 제공한다.
2. **모바일 동영상 등록과 원본 보관**: 현재 갤러리 `image/*`, 공통 intake의 IMG 검사 때문에 동영상 경로가 연결되지 않는다. 단순히 선택 제한만 풀지 말고 파일 크기·코덱·원본의 영구 보관·실패 복구까지 먼저 검증해야 한다. 이번 v289 영상 보고 기능은 이미 등록된 영상의 조회 기능이다.
3. **하루 마감 확인**: 기존 보고서·미배정 사진·저장 상태 화면을 연결하여 누락을 알려 주되 자동 현장 배정이나 자동 완료 처리하지 않는다.
4. **현장별 할 일 필터**: 기존 할 일 자료를 그대로 사용하고 현장 변경·보관·동명이인 처리부터 명확히 한다. 별도 할 일 저장소를 만들지 않는다.
5. **실제 휴대폰 확인**: 대표 폰에서 로그인/Drive 저장, 카메라·갤러리 권한, 오프라인→온라인 전환을 확인한다. 브라우저의 가상자료 시험과 별개다.
