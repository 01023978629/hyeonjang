# v274 복구·대기열 안전 보완 검증

기준: 운영 main `7971987` / `hyeonjang-v273-officeconnect`.
검증 후보: `hyeonjang-v274-recoveryguard`. 운영 배포는 하지 않았다.

## 구현 범위

- 로컬 스냅샷 복구: 손상 기록 사전 차단, 복구 전 안전판 true 확인, 빈 상태 보관,
  중복 실행 차단, 실패 시 재시도 가능, 클라우드 저장과 복구 결과 구분.
- 사진/저장 대기열: IDB 읽기 실패를 빈 큐로 대체하지 않음. 읽기·쓰기 실패 시
  기존 항목을 덮어쓰거나 전송/보관/삭제 완료로 표시하지 않음.
- 공개 셸·서비스워커 버전 일치. 새 업무 필드/서버/자동 실행 권한 변경 없음.

## 전체 회귀

최종 `tests/run-all.js`: **129개 중 129 통과, 0 실패**, 종료 코드 **0**.
12.9분, 동시 2, 재시도 없음. 신규 검사 2파일을 포함한 전체 집계다.
새 안전 시나리오 30개와 변이 8종도 통과/실패 검출 근거를 확인했다.
독립 검토에서도 손상 기록 차단과 정상 빈 기록 허용을 재확인했고 추가 blocker는 없었다.
로그: 작업 폴더 밖 `tmp/hyeonjang-level3-20260909/full-regression-verified.log`.

실행 설정: `HJ_TEST_JOBS=2`, 파일당 180초 제한·기존 재시도 규칙 유지.
격리 Chromium과 합성 자료만 사용한다. 별도 테스트용 네트워크 경계에서
로컬 앱 GET과 모의 relay만 허용하고 외부 실제 서비스 요청은 차단한다.

실행 이력도 보존한다.

- 첫 전체 실행 준비는 NODE_OPTIONS의 Windows 역슬래시 경로 파싱 오류로 검사 시작 전 종료됐다.
  전방 슬래시로 수정했으며 제품/검사 조건을 완화하지 않았다.
- 두 번째 전체 실행은 감사에서 손상 스냅샷 성공 오보고를 발견하여 소유한 시험 러너만 중단했다.
  해당 가드와 검사를 추가한 뒤 전체를 처음부터 다시 실행했다. 중단 실행은 통과로 세지 않는다.
- 세 번째 전체 실행은 129개 중 125 통과·4 실패(16.0분, 종료 코드 1)였다.
  별도 시험용 외부 통신 차단기가 검사의 임시 localhost 포트까지 막아
  apt-commercial-ui·legacy-commercial-gate·office-ops-conversion·office-ops-ui가
  ERR_BLOCKED_BY_CLIENT로 실패했다. 로컬 정적 서버의 GET만 추가 허용했고 외부 통신 차단은 유지했다.
  제품 코드·검사 단언·제한 시간은 바꾸지 않았다. 이 실패 실행도 보존한다.
  office-ops-isolation은 병렬 180초 시간 초과 뒤 기존 단독 재시도에서 133.7초로 통과했다.
- 통신 경계 수정 뒤 위 4개 파일을 먼저 다시 실행하여 4/4 통과(2.4분, 종료 코드 0)를 확인했다.
  이후 필터 없이 전체를 다시 실행하여 위 최종 129/129 결과를 얻었다.
  이 4개 통과를 전체 회귀 결과로 대체하지 않았다.
- 신규 복구 검사 초안에서 한 시나리오의 render 후속 처리가 다음 합성 상태에 영향을 주었다.
  시나리오마다 새 document 부팅 완료를 기다리도록 격리했고 보호 단언을 완화하지 않았다.

office-ops-isolation의 읽기 전용 진단에서는 2.50MB 소스를 변이마다 반복 분석하는
CPU 비용을 확인했다. 토큰화 1회 약 961ms, 토큰 482,694개였고 브라우저/운영 네트워크는
사용하지 않는다. 병렬 자원 경합은 시간 초과의 유력한 원인이나 전체 프로파일로 확정하지 않았다.
동일 후보 소스 분석 재사용은 후속 검사 성능 개선 후보이며 이번 검사·제한 시간은 유지했다.
