## 1. 사진 삭제·공유 할일 백업 안전

- 개별·일괄 사진 삭제 모두 앱 목록만 제거한다. 예전 개별 삭제의 PC 원본 직접 삭제 경로를 없앴다.
- 강제 안전 스냅샷 결과가 정확히 `true`일 때만 다음 단계로 간다. false·예외는 원본, 목록, 선택을 보존한다.
- 확인한 파일 객체·내용·제외 목록이 바뀌면 중단한다. 앱 상태와 Drive 제외 ID를 동일 IndexedDB 트랜잭션으로 저장하며 다른 탭의 저장시점/제외 목록을 비교한다.
- 공유 할일은 실제 변경 전에 원장 전체를 별도 Drive 백업 파일에 기록하고 내용을 다시 읽어 검증한다. 실패하면 변경하지 않는다.
- `오늘 할일 → 팀 공유 할일 → 공유 할일 백업·복원`에서 목록, 지금 백업, 전체 공유 할일 복원, 결과 미확인 요청 재시도를 제공한다.
- 복원은 **모든 현장의 공유 할일 전체 목록**을 선택한 백업으로 교체한다. 2차 확인, 현재 목록의 복원 직전 백업, revision 확인이 필요하다. 과거 ID는 삭제표식으로 보존하고 복원 내용은 새 ID로 생성해 오래된 요청이 덮어쓰지 못한다.
- 정상적인 백업·복원 대기 요청이 있을 때 기존 공유 할일 화면도 손상으로 오인하지 않고 전용 복원 화면으로 안내하며 일반 쓰기를 차단한다.

## 2. 기존 원본 재연결·서버 검증

경로: `사진 → 더보기/사진 도구 → 원본·영상 관리`, 또는 `사진 보관 상태 → 원본 재연결·사진/영상 전송`.

- 목록을 열기만 해서는 네트워크 전송·파일 권한 요청·사진 변경을 하지 않는다.
- 기존 파일 하나를 선택해 이름·크기·알려진 SHA-256을 검사하고 원본을 연결한다. 현장·작업 내용·동호수·날짜·OCR 등 기존 값은 보존한다. 같은 이름/크기의 후보가 여러 개면 자동 연결하지 않는다.
- 최초 원본 해시가 없는 자료는 명시적으로 선택한 파일의 해시를 기준으로 기록한다. 과거 원본과 동일하다는 소급 증명은 아니다.
- `[서버 확인]`은 실제 Drive 파일을 검사한다. 해시·크기까지 같은 경우와 단순 서버 파일 존재를 구분하며 확인 시각을 보여 준다. 회사 연결이 바뀌면 이전 검증 문구를 다시 사용하지 않는다.
- 서버 원본 참조와 원본 해시는 일반 저장·복원·편집 백업·paid 상태 재구성에 포함한다. 과거 백업으로 되돌릴 때 없는 새 원본 검증 정보를 남기지 않는다.

## 3. 사진·영상 원본 전송과 재시도

- 기존 `＋ 사진 추가`와 기존 압축 사진 중계 기능은 보존한다. 새 `사진·영상 원본 추가`는 별도 원본 전송 서버 기능 확인 후 사용한다.
- 모바일 사진/영상 선택 → 현장·작업명 확인 → 안전 백업 → 기록 저장 → 원본 전송 순서다. 같은 파일 재선택은 새 기록을 만들지 않는다. 이름·크기가 같아도 바이트가 다른 파일은 조용히 생략하지 않고 중단한다.
- 초기 상한: 파일 하나 100MiB, 한 번에 20개/합계250MiB. 1MiB 청크로 나누어 전송한다. 사진도 원본 바이트를 전송하며 원본 자체를 편집/압축하지 않는다.
- 서버는 사전 발급 Drive ID와 `uploadId`를 영구 기록한다. 중간/완료 응답 유실 시 같은 요청 번호로 확인하므로 재시도가 새 파일을 만들지 않는다.
- 브라우저는 연결별 전송 식별정보를 IndexedDB에 보관한다. 원본 Blob 자체는 영구 보관하지 않으므로 새로고침 후 같은 파일을 다시 골라야 할 수 있다. 사용자 원본은 지우지 않는다.
- 각 네트워크 응답에는 45초 확인 제한을 두고, 시간 초과는 실패 확정/성공 확정 대신 같은 요청 재확인 대상으로 남긴다.
- 성공은 서버의 현재 크기·SHA-256 일치와 앱 연결 저장까지 확인한 경우만 표시한다. 연결 URL/토큰이 바뀌면 다른 서버에 이어 보내지 않는다.
- 다른 인증된 기기는 원본 전송 정보가 포함된 최신 회사 자료를 불러온 뒤 영상의 `[서버 원본 불러와 재생]`을 사용할 수 있다. 공개 Drive 링크나 공유 권한 변경을 만들지 않는다.
- 부분 읽기 응답의 범위/크기/해시를 검사하고 전체 바이트 SHA-256도 다시 검사한 뒤 기기 Blob URL을 재생한다. 직접 스트리밍 URL이나 백그라운드 전송 서비스는 아니다.

## 구현·배포 파일

- 공개 앱: `index.html`, `media-safety.js`, `shared-todo-backup.js`, `sw.js`. `privacy.html`과 앱 하단 안내에는 회사 서버 공유·원본 보존·재시도 기록 보관을 실제 동작에 맞게 추가했다.

- `scripts/stage-pages.mjs`는 공개 셸7개만 포함한다. 앱 데이터·백업·테스트·Apps Script 소스를 공개하지 않는다. SW도 추가 공개 JS 두 개만 명시 허용한다.
- 보호 검사 기준 커밋을 바꾸거나 서버 폴더를 통째로 예외 처리하지 않았다. 새 모듈 경로·dispatch·scope만 정확히 허용하고 범위 확대/인증 우회 변이를 검사한다.

## 알려진 운영 한계

1. 기존 회사 토큰 인증을 사용한다. 직원별 역할·퇴사자 권한 회수·읽음 확인을 새로 구현한 것은 아니다.
2. 원본 전송 서버 journal 초기 상한은 **완료 영수증을 포함해256건**, 전체 Script Properties400KiB다. 한도에서 신규 작업을 안전하게 중단한다. 장기 운영 전 Drive 영수증 저장소 등으로 이관 검증을 포함한 확장이 필요하다. 영수증 자동 삭제는 금지한다.
3. 공유 할일은 tombstone 포함5000건, 일반 receipt2048개, 복원 영수증128개 등 기존/추가 상한이 있다. 복원은 새 ID를 생성하므로 빈번한 전체복원은 용량을 사용한다.
4. 현재 공유 원장 자체가 손상되면 ID/revision을 추정하지 않고 자동 복원을 중단한다. 별도 Drive 백업은 보존되므로 별도 복구 진단 대상이다.
5. Apps Script/Drive 호출 한도, 네트워크, 휴대폰 메모리/코덱에 따라 대용량 보관·재생 성공 범위가 달라진다. 100MiB는 코드 상한이지 실제 기기 성공 보장이 아니다. 전송 중 화면을 유지하는 사용 흐름이다.
6. 실제 운영 Watchdog는 로컬과 다르다. 전체 폴더 `clasp push`를 하지 않는다. 별도 승인 후 운영 원본 보존·최소 모듈 반영과 기존 배포 URL 유지가 필요하다.
