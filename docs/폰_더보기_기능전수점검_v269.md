# 폰 ‘더보기’ 기능 전수 점검 — v269

작성일: 2026-09-07. 조사 기준: v268 로컬 후보 `efbb822`의 `index.html`.
이 문서는 소스 연결 감사이며, 112개 기능을 운영 계정으로 실행했다는 뜻이 아니다.
전화번호·계정·토큰·고객 자료를 문서에 옮기지 않았으며 실제 발송·복원·반출·서버 쓰기를 수행하지 않았다.

## 1. 구조와 전체 수

정상 연결은 `openMoreSheet()` → `openMoreSheetV2()` → `moreDispatch(action)` → `moreActionHandler(action)`이다.
같은 이름의 뒤쪽 재정의, 별도 카탈로그 주입, 추가 wrapper는 기준 소스에서 발견되지 않았다.

- `MORE_CATS`: 6분류, 112개 고유 action. 모든 action에 대응 분기와 함수가 존재한다.
- 바로가기: 서류·견적·연락처·현장별 4개. action 카탈로그와 별도 배열이다.
- AI 비서 배너: `aiAgent()` 1개. AI 도우미의 최종 목적지와 동일한 의도적 바로가기다.
- 최근 사용: 위 112개 중 최대 6개를 다시 노출한다. 기능 수에는 중복 합산하지 않는다.
- 소스의 ‘91개’ 주석은 오래된 값이다. UI의 기능 수는 배열 합계로 계산한다.
- 구형 fallback에는 별도의 오래된 메뉴 HTML이 남아 있다. 정상 V2 카탈로그와 같은 기능 구성이라고 가정하면 안 된다.

기준 소스 주요 위치: CSS 129~142, `moreActionHandler` 5805, `openMoreSheet` 5806,
`MORE_CATS` 19773, `moreGetRecent` 19816, `openMoreSheetV2` 19826, `moreDispatch` 19889.
줄번호는 후속 구현으로 바뀔 수 있으므로 함수명을 우선 사용한다.

## 2. 위험 표시를 읽는 방법

아래 표는 **메뉴 진입 시점과 후속 기능의 검증 경계**를 구분한다. ‘화면’은 연결 목적지를 뜻하며 저장이 절대 없다는 보증이 아니다.

- **화면**: 조회·안내·모달 또는 앱 탭 진입. 데이터가 있는 경우 후속 버튼은 별도로 점검한다.
- **편집 확인**: 추가·수정·승인·복구가 가능한 화면. 합성 자료로만 후속 버튼을 시험한다.
- **설정 확인**: 계정·AI·서버·권한·기기 기능 또는 PC 폴더 연결이 필요할 수 있다.
- **공유 확인**: 초안·공유·공개·다운로드가 가능한 화면. 실제 수신처 발송·공개는 이번 감사에서 하지 않는다.
- **직접 실행**: 메뉴를 누르는 것만으로 네트워크 조회·AI 요청·파일 내보내기·큐 처리 또는 상태 변경 경로에 들어간다. 전수 연결 시험에서는 대상 함수를 대역으로 바꾼다.

## 4. 발견 사항과 v269 수정 검증 항목

아래는 **발견 및 구현 검증 대상**이다. 작성 시점에 최종 통과를 단정하지 않는다.
최종 구현 여부·검사 결과는 v269 테스트 리포트에서 별도로 확정한다.

| 발견 사항 | 기준 소스 근거 | 수정 및 회귀 조건 |
|---|---|---|
| 서류·연락처 등 바로가기 검색 누락 | `navShortcuts`는 별도 배열, 검색은 `MORE_CATS`만 조회 | 바로가기와 action 모두 검색. 검색 결과 클릭 목적지 검사 |
| 띄어쓰기·다른 업무 표현으로 찾기 어려움 | 검색은 label/category의 소문자 `includes`뿐 | 공백 정규화, 설명·키워드 검색. 빈 결과·검색 지우기·한글 조합 검사 |
| 최근 기록이 배열이 아니면 구형 화면으로 추락 | `moreGetRecent()`가 JSON을 그대로 반환하고 즉시 `.map()` | 객체·null·숫자·알 수 없는 action·중복 기록을 안전 처리. 정상 화면 유지 |
| 비동기 기능 실패가 디스패처에 전달되지 않음 | `moreActionHandler`가 async 함수 결과를 반환하지 않음 | 반환·await·실패 안내 연결. 합성 Promise rejection으로 검증 |
| ‘만물인테리어 열기’ 목적지 혼동 | `openDrive`는 Drive 폴더로 연결 | 폴더 목적을 이름/설명에 명시. 홈페이지 목적지로 임의 변경하지 않음 |
| ‘백업 복원’이 폰 일반 복원으로 보임 | `openRestore`는 `requireEditMode`와 PC `dirHandle/_백업` 사용 | PC 폴더 백업임을 설명. 기기 스냅샷·백업 센터와 구분 |
| 글씨 확대 설정이 메뉴 텍스트에 미치지 못함 | `.more-chip-label`의 고정 10.5px와 2줄 clamp | 320~430px 및 큰 글씨에서 이름 식별·탭 크기·가로 넘침 확인 |
| 메뉴에서 연 기능을 닫은 뒤 초점 상실 가능 | `closeSheet(false)`로 클릭 버튼 제거 후 `openModal`이 현재 초점 기억 | 기능 모달 종료 시 유효한 ‘더보기’ 버튼/적절한 화면으로 초점 복귀 |
| 검색 결과 개수·빈 결과가 보조기기에 자동 전달되지 않음 | 검색 결과는 일반 div, 명시 label/status 없음 | 검색 label·상태 안내·지우기 버튼·키보드 동선 검사 |
| 새 사진 관리 기능을 더보기 검색으로 찾을 수 없음 | `photoToolsView`/`photoSourceView`가 기존 112 카탈로그에 없음 | 사진 도구/보관 상태 등 추가 시 고유 action·안전 진입 보호를 함께 검사 |
| 구형 fallback은 클릭 div·닫기/초점/뒤로가기 계약이 정상 V2와 다름 | `openMoreSheet`의 예외 뒤 별도 HTML | 입력 손상으로 fallback 진입하지 않도록 방어. 예외 화면도 명시 오류/접근성 유지 |
| 날씨 조회 실패 시 닫기 UI가 사라짐 | `weatherSmart` catch가 `#modalRoot.innerHTML` 전체를 오류 div로 대체. `.modal`이 없어 Escape 처리도 건너뜀 | 목적 화면의 기존 P2 결함. 합성 `weatherFetch` rejection으로 재현하고 정상 `openModal` 오류 화면에서 닫기·뒤로가기·body 잠금 해제 확인 |

동일 기능 키의 중복이나 대응 함수 자체가 없는 오연결은 발견되지 않았다.
‘연간 결산/연말 결산’, ‘전/후 비교 카드/전후 갤러리’, ‘고객 문자/문자 센터’는 다른 함수이므로
이름이 비슷하다는 이유로 삭제·합치지 않는다. 우선 설명으로 용도를 구분한다.

### 구현 담당자가 확정한 제한적 개선 범위

- `restore` 표시명은 **PC 폴더 백업 복원**, `opendrive` 표시명은 **구글드라이브 만물 폴더**로 명확히 한다. 위 전수표는 변경 전 기준 이름을 보존한다.
- `sheet`, `aibrain`, `autopilot`, `fullxlsx`, `undo`는 **더보기에서 진입할 때만** 실행 전 확인/취소 화면을 둔다. 기존 전역 함수와 다른 화면의 동작 계약을 변경하지 않는다.
- 실행 전 확인에는 실행할 일과 영향 범위를 표시한다. 취소·닫기·뒤로가기에서는 목적 함수를 한 번도 호출하지 않는다. 확인한 경우에만 한 번 호출한다.
- 이 확인 화면 추가는 실제 운영 계정의 실행 승인이나 서버 호출 시험을 대신하지 않는다.
- 최종 검증은 **112개 독립 stub 연결 검사**와 **선정한 비파괴 기능의 실제 UI 열기 검사**로 구분하여 보고한다. stub 통과를 실제 AI·Sheets·발송 성공이라고 표현하지 않는다.

### v269 구현분 독립 재검토에서 확인한 개선

v269 후보의 현재 소스를 다시 읽고, 운영 요청을 차단한 별도 Chromium 컨텍스트에서 아래 범위만 확인했다.
이 절의 확인과 신규 기능 테스트/최종 전체 회귀의 완료 여부는 구분한다.

- **목록·검색**: 112개 고유 action과 112개 설명이 일치하며 설명 누락·중복 action은 0개다. 바로가기 검색을 포함하고 공백 없는 ‘프로젝트별문서’가 `nav:docs`로 연결되는 것을 확인했다.
- **최근 사용·즐겨찾기**: JSON 배열 여부, 문자열·허용 action 필터, 중복 제거, 최대 6개 처리가 소스에 반영됐다. 즐겨찾기는 이 기기의 별도 UI 설정이며 백업/업무 데이터 구조를 확장하지 않는다. 손상값·편집 중 미실행 등 전수 시나리오 결과는 신규 테스트 리포트에서 확정한다.
- **실행 오류**: 기존 action 분기에서 목적 함수의 반환값을 전달하고 `moreDispatch()`가 await/실패 안내를 처리한다. 알 수 없는 action은 실행하지 않는다.
- **실행 전 확인**: 확인 대상이 `sheet`, `aibrain`, `autopilot`, `fullxlsx`, `undo`의 정확히 5개임을 정적으로 확인했다. Sheets 목적 함수를 대역으로 치환한 독립 UI 검사에서는 취소 시 0회, 확인 시 1회 호출됐다. 실제 Sheets 요청은 하지 않았다.
- **초점**: 모바일 모드에서 확인 화면을 취소하거나 대역 목적 모달을 닫으면 ‘더보기’ 버튼으로 복귀하는 것을 확인했다.
- **작은 화면·큰 글씨**: 320×568에서 보통/크게/아주 크게 메뉴의 가로 넘침 및 44px 미달 표시 버튼이 없었다. 처음 발견한 big1의 ‘구글드라이브 만물 폴더’ 3줄 잘림은 좁은 화면 1열 처리 후 재검사에서 0건이었다. 모든 실제 휴대폰/글꼴 조합을 시험했다는 뜻은 아니다.
- **설명 정확성**: Drive 폴더와 PC 폴더 백업 복원 목적을 이름으로 구분했다. 스마트 알림은 ‘브라우저 알림 켜기·끄기·미리보기’, 사진 배정 점검은 ‘GPS 배정 오류·중복 의심 사진 점검’으로 실제 기능과 맞췄다.
- **날씨 화면**: 성공·실패 모두 `openModal()`을 사용해 닫기 구조를 유지한다. 합성 날씨 성공/실패에서 닫기 버튼을 확인했고 Escape 후 배경 잠금 해제를 확인했다. 지연 응답 중 다른 모달을 연 검사에서는 새 모달이 보존됐다. 후속 AI 결과에도 이전 버튼/결과 영역의 연결 여부 가드가 반영됐다. 실제 날씨·AI 네트워크 성공은 시험하지 않았다.

독립 재검토에서 남은 차단 결함은 발견하지 않았다. 최종 배포 가능 판정은 마지막 소스의 신규 검사·변이·전체 회귀와 별도 배포 승인을 근거로 한다.

## 5. 직접 실행 위험의 구체적 근거

- `exportToSheet()`는 `getSheetToken()` 뒤 Sheets `POST`(새 파일), `PUT`(견적·정산 값)을 호출한다. 메뉴 연결 전수 검사는 이 함수를 절대 운영 토큰으로 실행하지 않는다.
- `aiOpsBrain()`은 AI 설정이 있으면 진행 현장 수·당일 일정·대기 큐 요약을 만들어 `aiAsk()`에 보낸다. 메뉴를 여는 것과 AI 요청을 보내는 것은 다르다.
- `aiAutoOperateView()`는 즉시 `aiAutoOperate()`를 호출한다. 큐 점검·승인 대기 분류·안전 작업 실행·운영 로그 기록이 있으므로 단순 조회 대역으로 취급하지 않는다. 기존 승인/SAFE_AUTO 범위는 확대하지 않는다.
- `officeOpsView()`는 `officeOpsRefresh()`, `kakaoOpenInbox()`는 `kakaoFetch2()`를 진입 시 호출한다.
- `allProjectsMap()`은 지도 모듈·타일 및 필요 시 `ensureProjGeo()`로 주소 좌표를 확보한다. 주소가 외부 조회에 쓰이는지와 좌표 저장 영향을 실제 고객 자료 없이 점검한다.
- `weatherSmart()`와 `runDiagnostics()`는 네트워크 조회가 있다. 오프라인 실패 화면도 별도로 점검한다.
- `exportFullXlsx()`는 전체 장부 파일을 내보낸다. 고객·수금·지출이 들어갈 수 있으므로 합성 fixture 외 실제 자료로 실행하지 않는다.
- `sendPhotoBundles()`, `shareBizCard()`, `msgCenterView()`는 먼저 선택/작성 화면을 연다. 이 사실을 ‘발송 완료’로 기록하지 않는다.

## 6. 테스트 권한과 완료 판정 경계

### 자동화 가능한 범위

1. 빈 별도 브라우저 컨텍스트 + 합성 fixture. 운영 저장소·실제 Drive 자료를 가져오지 않는다.
2. 112개 action의 목적 함수는 spy/stub으로 바꿔 키·분기·호출 횟수·인자만 검사한다. 모든 버튼을 운영 함수 그대로 순회 클릭하지 않는다.
3. 바로가기 4개는 실제 앱 탭 전환을 검사하되 금액·수금·사진·프로젝트 구조가 전후 동일한지 비교한다.
4. 검색: label/분류/설명/공백/한글 조합/빈 결과/지우기/바로가기. recent: 잘못된 JSON·비배열·허용되지 않은 키·중복·최대 개수.
5. 실패 처리: 동기 throw와 비동기 rejection 모두 안내가 보이고 다시 메뉴를 열 수 있는지 확인한다.
6. 320/360/390/430px, 큰 글씨 2단계에서 가로 넘침·이름 잘림·탭 영역·검색 키보드·닫기/Escape/휴대폰 뒤로가기·초점 복귀를 검사한다.
7. 기존 `mobile-shell-a11y`, `mobile-field-flow`, `mobile-back`, `mobile-nav-scroll`과 정적 필수 검사 및 최종 전체 회귀를 유지한다.
8. 새 검사는 변이로 보호 동작 제거 시 실제로 실패하는 것을 확인한다. 검사를 느슨하게 하여 통과시키지 않는다.
9. 선정한 비파괴 UI 열기는 예를 들어 사용 가이드·사용설명서·읽기 전용 보관 상태 등의 화면을 합성 fixture에서 실제로 열어 제목·닫기·레이아웃을 확인한다. 추가/저장/복구/공유/AI 실행 버튼은 누르지 않는다. 실제로 확인한 화면 이름과 개수만 최종 리포트에 기록한다.

### 이번 감사에서 하지 않는 일

- 실제 문자·알림톡·카카오 발송, 고객 페이지 공개, 권한 발급·변경.
- 운영 OAuth·키 설정, 실제 AI 유료 요청, 실제 Sheets/Drive 생성·수정.
- 실제 사진 배정·삭제·복원·파일 이동, 수금·견적 금액·계산·승인 계약 변경.
- 브랜치 업로드·PR·main 병합·Pages 또는 Apps Script 배포.

실제 폰의 카메라/갤러리·마이크·파일 공유창·앱 전환·권한 UI는 대표 실기기 확인이 남는다.
소스상 목적 함수 존재와 합성 자료 테스트 통과만으로 운영 계정의 연결 성공이나 발송 성공을 단정하지 않는다.
