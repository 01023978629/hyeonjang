# 직원 작업실 설치·연결 절차서 (대표용)

직원 작업실(`team.html`)을 실제 직원 계정으로 쓰기 위해 **대표가 손으로 하는 일**만 순서대로 적었다.
서버 동작·제한의 근거는 `apps-script-team-ops/README.md`, 화면 경계는 `TEAM-WORKSPACES-v329.md`·`TEAM-PROJECT-CLAIMS-v330.md`.
이 문서의 어느 단계도 저장소에서 자동으로 실행되지 않는다. GitHub 병합만으로 서버가 바뀌지 않는다.

> 실제 주소·폴더 ID·userId·비밀번호를 이 문서·카톡·Git 에 적지 마라. 스크립트 속성과 이 기기 화면에만 넣는다.

## 0. 시작 전에 정할 것 — 직원 로그인에 쓸 '회사 단지'

직원 작업실은 비밀번호를 따로 두지 않는다. **관리사무소 포털 계정으로 로그인**하고, 그 계정이 어느 단지(officeId) 소속인지로 회사 직원임을 확인한다.

- 쓸 단지는 **회사만 통제하는 단지**여야 한다(예: 포털을 처음 설치할 때 만든 '만물인테리어' 단지). 고객 아파트 관리소장(manager_chief)이 있는 단지는 쓰면 안 된다 — 그 소장이 직원 비밀번호를 재발급할 수 있다.
- 포털에 아직 회사 단지가 없으면 진행하지 말고 먼저 정한다(포털 관리자 화면에는 단지를 새로 만드는 버튼이 없다 — 개발 쪽에 요청).
- 필요한 값 두 개를 미리 찾아 둔다(포털 스프레드시트 → `Users` 탭, 대표 본인 행): **userId**(`usr_…`)와 **officeId**.

## 1. Drive 비공개 폴더 만들기

1. drive.google.com → **새로 만들기 → 새 폴더** → 이름 예: `직원작업실-자료`.
2. 폴더를 **아무에게도 공유하지 않는다**(편집자·뷰어·링크 공유 모두 없음). 공유돼 있으면 서버가 스스로 멈춘다.
3. 폴더를 열고 주소창 `…/folders/` 뒤의 문자열이 **폴더 ID** 다.

## 2. Apps Script 새 프로젝트에 파일 붙여넣기

1. script.google.com → **새 프로젝트** → 이름 예: `직원작업실 서버`. (사진 중계·관리사무소 포털 프로젝트에 붙이지 마라.)
2. 저장소 `apps-script-team-ops/` 의 네 파일을 같은 이름으로 만든다: `Code.gs`, `TeamPure.gs`, `TeamProjects.gs`, `TeamEvidence.gs` — 각 파일 내용을 통째로 붙여넣는다. 기본 `코드.gs` 는 지운다.
3. 왼쪽 **⚙ 프로젝트 설정 → 「편집기에 "appsscript.json" 매니페스트 파일 표시」** 를 켜고, `appsscript.json` 을 저장소 내용으로 바꾼다.

## 3. 스크립트 속성 넣기

**⚙ 프로젝트 설정 → 스크립트 속성 → 속성 추가** 로 여섯 개:

| 속성 | 값 |
| --- | --- |
| `COMPANY_ENABLED` | `1` |
| `COMPANY_PORTAL_URL` | 관리사무소 포털의 웹 앱 주소(끝이 `/exec`) |
| `COMPANY_FOLDER_ID` | 1단계 폴더 ID |
| `COMPANY_OFFICE_ID` | 0단계 officeId (로그인 코드 아님) |
| `COMPANY_OWNER_USER_ID` | 0단계 대표 userId (임시 — 7단계 뒤 자동 삭제) |
| `COMPANY_OWNER_NAME` | 대표 표시 이름 (임시 — 7단계 뒤 자동 삭제) |

## 4. 배포

1. 오른쪽 위 **배포 → 새 배포 → 유형 선택(⚙) → 웹 앱**.
2. **다음 사용자 인증 정보로 실행: 나** · **액세스 권한이 있는 사용자: 모든 사용자**. ('나만'으로 하면 직원 작업실에서 연결되지 않는다. 모든 요청은 서버가 포털 로그인으로 다시 확인한다.)
3. **배포** → 권한 승인(Drive·외부 요청) → 나온 **웹 앱 URL**(…/exec)을 복사해 둔다.

## 5~6. (관리사무소 포털) 직원 계정 만들기

1. 관리사무소 포털 관리자 화면(`office-admin.html`)에 0단계의 회사 단지 관리자 계정으로 로그인.
2. 직원마다 **사용자 추가** — 이름·이메일·발급 비밀번호. 포털 역할은 회사 권한과 무관하다(회사 권한은 9단계에서 따로 준다).
3. 비밀번호는 직원에게 직접 전달한다(카톡 그룹방에 올리지 않는다).

## 7. 회사 자료 만들기(부트스트랩) — 한 번만

1. Apps Script 편집기 위쪽 함수 목록에서 **`companyBootstrapFromProperties_`** 선택 → **실행**.
2. 성공하면 기본 4팀(대표·관리 / 누수·배관팀 / 인테리어팀 / 관리사무소 대응팀)과 대표 1명이 만들어지고, 임시 속성 두 개(`COMPANY_OWNER_…`)가 지워진다.
3. 이미 만든 적이 있으면 `already-configured` 로 멈춘다 — 정상이다. 덮어쓰지 않는다.

## 8. 앱에 주소 넣기

1. 폰에서 현장 앱 → 첫 화면 「직원 작업실 · 업무 배정·검수」 (또는 주소 `…/team.html`).
2. 로그인 칸 아래 **「서버 연결 설정 · 대표」** 를 펼치고 4단계 웹 앱 URL 을 붙여넣기 → **[연결 확인 후 저장]**.
3. '연결됐습니다' 가 나오면 이 기기에 주소가 저장된다(비밀값 아님). 실패하면 화면이 이유를 말한다:

| 화면 문구 | 고칠 곳 |
| --- | --- |
| 주소 형식이 다릅니다 | 4단계 URL 을 그대로 다시 복사(끝이 `/dev` 인 테스트 주소 X) |
| 서버에 닿지 못했습니다 | 4단계 '액세스 권한' 이 '모든 사용자' 인지, 인터넷 연결 |
| 회사 팀 업무 서버의 응답이 아닙니다 | 사진 중계·포털 주소를 넣지 않았는지, 2단계 파일 네 개를 붙이고 **새 버전**으로 배포했는지 |
| 스크립트 속성이 덜 들어갔습니다 | 3단계 `COMPANY_ENABLED`·`COMPANY_PORTAL_URL`·`COMPANY_FOLDER_ID`·`COMPANY_OFFICE_ID` |

직원 폰은 **각자 한 번** 같은 주소를 넣는다(대표가 주소를 알려 준다). 모든 폰에 고정하려면 개발 쪽에 `team-config.js` 에 주소를 넣어 배포해 달라고 한다 — 그러면 입력칸 대신 고정 주소가 쓰인다.

## 9. 대표 로그인 → 직원 권한 연결

1. 0단계 회사 단지 코드·대표 이메일·비밀번호로 로그인.
   - '회사 자료가 아직 만들어지지 않았습니다' → 7단계를 안 했다.
   - '회사 팀 권한이 없거나…' → 3단계 `COMPANY_OWNER_USER_ID` 가 대표 userId 와 달랐다.
2. 직원이 한 번 로그인하면 화면의 「회사 권한 연결용 내 식별정보」(userId·officeId)를 대표에게 보낸다.
3. 대표: **직원·팀 설정 → 직원 권한 연결** → 이름·userId·역할(대표·관리자 / 팀장 / 직원 / 외주)·소속 팀 → 저장.

## 10. 권한 점검 누르기

대표 계정으로 **권한 점검 → [전 직원 권한 점검]**. 아무것도 저장하지 않는다. 서버가 직원마다 실제로 무엇을 보여 주는지 계산해 오고, 화면이 역할 규칙과 맞춰 본다.

읽는 법:

- `✓` 규칙대로. 예: `팀장 김OO — 자기 팀(인테리어팀) 업무 2건만 본다 ✓`, `외주 OO — 배정·완료 승인 권한 없음 ✓`.
- `✗` 문제. 예: `기대: … 2건만 본다 — 서버는 3건을 보여 준다` → 서버 파일이 저장소와 다르다. 2단계 파일을 다시 붙이고 새 버전으로 배포.
- `!` 확인 필요. 예: `COMPANY_OWNER_NAME 가 남아 있다`(스크립트 속성에서 지운다), `관리사무소 대응팀: 소속 직원이 없어 대표만 배정`(직원을 넣거나 무시), `연결한 단지 ID 가 회사 신원 단지와 달라 로그인할 수 없다`(그 직원을 다시 연결).
- 설정 줄(`COMPANY_FOLDER_ID 있음 (값은 표시하지 않음)`)은 값이 들어 있는지만 말한다. 값 자체는 화면에 나오지 않는다.
- '서버 코드가 권한 점검 이전 버전입니다' → 2단계 파일을 새로 붙이고 **배포 관리 → ✏ 수정 → 버전: 새 버전 → 배포**(주소는 그대로).

그다음 **실제 확인**: 팀장·직원·외주 계정으로 각각 로그인해 **권한 점검 → [내 권한 확인]**. 모두 ✓ 이고 '대표 전용 권한 점검은 서버가 거절한다 ✓' 가 나와야 한다. 하나라도 ✗ 면 그 계정은 쓰지 말고 개발 쪽에 화면 그대로 보낸다.

## 11. 현장 앱의 기존 업무 옮기기(선택)

현장 앱 → **팀 업무·인수인계** → **[직원 작업실로 초안 보내기]**(이 기기에 8단계 주소가 저장돼 있을 때만 보인다) → 확인 창 → 직원 작업실이 열리면 **대표 계정**으로 로그인 → 「현장 앱에서 보낸 업무 초안」 → **[불러와서 한 건씩 검토]** → 한 건씩 팀·담당자 정하고 저장.

- 저장을 누르기 전에는 서버에 아무것도 올라가지 않는다. 현장 앱의 원래 업무는 지우거나 바꾸지 않는다(자동 동기화 없음).
- 넘긴 초안은 이 브라우저에 하루만 남고, 한 번 불러오면 지워진다. 다른 폰으로는 넘어가지 않는다 — 그때는 [JSON 파일로 내려받기]를 쓴다.
- **보내기와 열기는 같은 앱(같은 브라우저) 안에서** 한다. 초안과 8단계 주소는 그 브라우저 저장소에만 있다. 아이폰 홈 화면에 설치한 앱은 Safari 와 저장소를 따로 쓰므로, 설치 앱에서 보냈으면 직원 작업실도 설치 앱 안에서 연다(설치 앱으로 떠 있으면 [보내기]가 같은 화면에서 직원 작업실로 옮겨 준다). Safari 에서 따로 연 직원 작업실에는 초안이 보이지 않는다 — 그때는 8단계 주소도 그 Safari 에 다시 넣어야 한다.
- 전달함은 **대표 계정에만** 보인다(팀장·직원으로 로그인하면 보이지도 지워지지도 않는다). 초안에는 모든 팀의 현장명(동·호수 포함 가능)이 들어 있기 때문이다.
- 초안 중 형식이 맞지 않는 건은 현장 앱이 보내기 전에 빼고 몇 건 뺐는지 말한다. 그래도 직원 작업실이 읽지 못하면 묶음을 버리고 '읽지 못해 버렸습니다' 라고 알린다 — 현장 앱에서 다시 보낸다.

## 하지 않는 것

- 문자·카톡·푸시 자동 발송 없음. 직원 비밀번호를 만들거나 저장하지 않음.
- 기존 공용 키(APP_TOKEN)를 아는 직원의 대표 앱 접근은 이 설치로 막히지 않는다(README 「활성화 전 필수 확인」).
- 모의 검사 통과는 실계정 확인이 아니다. 10단계를 실제 계정으로 끝낸 날짜를 기록해 둔다.
