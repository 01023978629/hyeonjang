## 검토와 수정

| 문제 | 수정 |
|---|---|
| 사진 선택 확인/처리 중에도 앱 업데이트가 캐시를 정리하고 새로고침할 수 있음 | 확인창·처리 중 업데이트 차단, 저장/버전 조회 후 재확인, 700ms 예약 새로고침 직전 재확인 |
| 업데이트의 비동기 대기 중 새 사진 추가가 시작될 수 있음 | 버전 조회부터 예약 새로고침까지 임시 잠금으로 갤러리·촬영·확인창 진입 상호 차단 |
| 응답 정체가 새 임시 잠금을 계속 유지할 수 있음 | 업데이트 대기에 총 15초 제한. 실패 안내 후 잠금 해제, 늦은 조회 응답으로 후속 새로고침을 실행하지 않음 |
| 사진 확인/첫 읽기에서는 아직 dirty=false라 이탈 경고 조건에 포함되지 않음 | 브라우저 beforeunload 경고 조건에 사진 확인창/처리 중 포함 |
| 입력한 작업명·공정명으로 사진을 찾을 수 없음 | 기존 `_worklabel`·`_phase`를 사진 검색/통합 검색에 포함, 공백·대소문자 차이 허용 |
| 통합 검색의 사진 결과를 눌러도 이전 검색어가 남음 | 사진 결과 버튼에서 검색어를 사진 탭/입력칸에 전달, 중복만 보기 해제. Enter/Space와 44px 터치 영역 지원 |
| 태그 검색 확장으로 오더에 다른 동·호 사진이 섞일 위험 | 오더 사진 집계/전후 비교/오더 경유 보기에는 기존 연결 기준 유지. 직접 검색할 때만 작업명 검색으로 복귀 |

## 데이터와 안전 경계

- 저장 구조/직렬화 키, Apps Script, 사진 중계 큐 계약은 변경하지 않음.
- 작업명/공정은 이미 저장하던 필드를 읽기만 함. 검색어/오더 보기 범위/업데이트 잠금은 임시 화면 상태.
- 새 사진 선택 직전 업데이트가 먼저 시작되면 업데이트 후 다시 선택하도록 안내하며 임의로 가져오지 않음.
- 검색으로 파일·현장·선택 목록을 수정하지 않음. 삭제·자동 배정·실제 전송·공개 발행 없음.
- 앱의 업데이트 버튼 보호와 브라우저 이탈 경고는 다름. 모바일 OS 강제종료/앱 전환 때 `beforeunload`는 보장되지 않으므로 사진 원본 보관이 계속 필요함. [MDN beforeunload 안내](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)
- 실제 휴대폰의 카메라/갤러리 권한·HEIC·실제 Drive 전송 검증은 별도이며 가상 사진 자동 테스트로 대체했다고 보고하지 않음.

## 배포 후 대표 확인

1. 운영 사진 원본 백업을 확인하고 새 버전을 수동 적용.
2. 테스트 사진을 선택한 확인창에서 앱 새로고침 버튼을 눌러 사진 확인을 먼저 마치라는 안내 확인.
3. 사진에 입력한 작업명 일부로 검색, 통합 검색 사진 결과에서 사진 목록으로 이동 확인.
4. 오더의 사진 장수와 사진 보기 결과가 같고, 일반 검색으로 전환하면 작업명으로도 검색되는지 확인.
